# OmniBridge 0.3.0-alpha27 — итоговый отчёт

## Результат

Backend alpha18 сохранён, но схема запуска полностью исправлена. В Windows-пакете теперь один `OmniBridge.exe`, который запускает встроенный Core, одно главное окно и Tray с единым lifecycle.

## Исправления alpha27 по фактической проверке Windows

- пункт sidebar теперь содержит и синюю иконку, и видимую подпись `Интеграция`;
- NotifyIcon создаётся, получает иконку и становится видимым до необязательного расширенного меню;
- если красивая Tray-панель не поддерживается конкретной конфигурацией Windows, автоматически подключается функциональное резервное меню, а левый клик по значку всегда возвращает окно;
- при отсутствии Tray приложение не прячется бесследно, а использует обычное сворачивание в панель задач;
- список изображений Tray переведён с проблемного для Windows PowerShell 5.1 generic-типа на совместимый `ArrayList`;
- первое скрытие сопровождается уведомлением «OmniBridge работает в Tray»;
- яркие hover-обводки удалены из общей темы кнопок, заголовка окна, навигации и ComboBox.

## Исправление стартового падения alpha24

Скриншот подтверждает, что Core успевал запуститься, после чего дочерний WPF controller завершался с кодом 1. Регрессия находилась в новом C#-классе оформления Tray: `Add-Type` компилировал типы WinForms/System.Drawing без compile-time references, что несовместимо с частью конфигураций штатного Windows PowerShell 5.1.

В alpha27 C# renderer удалён. Tray использует штатный `ToolStripProfessionalRenderer`, а оформление задаётся безопасными свойствами PowerShell. Ошибки AppUserModelID, иконки или расширенного Tray перехватываются отдельно и не блокируют запуск главного окна. Launcher также читает хвост `logs/ui.log` и показывает реальную диагностическую ошибку, если controller всё же не стартует.

## Почему раньше появлялся PowerShell и оставались процессы

Предыдущая схема состояла из пяти EXE. Desktop и Tray были Go-launcher-обёртками, каждая запускала отдельный `powershell.exe`. Core продолжал работать после закрытия Desktop намеренно. Поэтому окно, Tray и Core жили раздельно, а панель задач могла показывать PowerShell.

## Новая схема

- `OmniBridge.exe` поднимает Core и ждёт `/health`;
- этот же EXE запускает единственный WPF controller;
- Tray создаётся внутри того же controller и управляет уже существующим окном;
- сворачивание скрывает окно и убирает кнопку панели задач;
- левый клик по Tray показывает и активирует то же окно;
- крестик или Tray → «Выход» отправляет Core shutdown, освобождает NotifyIcon и завершает приложение;
- если UI аварийно завершился, родительский OmniBridge останавливает Core;
- «Перезапустить OmniBridge» использует restart marker и перезапускает Core/UI внутри родительского EXE;
- релизная сборка больше не создаёт отдельные Desktop, Tray, Setup и Accounts EXE.

## Иконка Windows

- WPF `Window.Icon` загружается из `assets/omnibridge.ico`;
- процесс получает AppUserModelID `OmniBridge.UniversalAIGateway`;
- единый EXE собирается как Windows GUI и содержит `.rsrc`, icon и PerMonitorV2 manifest.

## Интерфейс

- sidebar стал холоднее: `#07172A`;
- добавлены правые скругления 12 px;
- у пункта VS Code удалена подпись, оставлена синяя иконка `#28A9FF`;
- цвет `INFO` перенесён в XAML DataTemplate и жёстко задан бежевым `#D8C7A6`; WARN/ERROR/DEBUG используют отдельные DataTrigger.
- исправлена Windows PowerShell 5.1-совместимость стартовой инициализации Tray;
- добавлен fail-open запуск UI при необязательной ошибке Tray/AppID/icon;
- вместо безликого `exit code 1` выводится фактическая ошибка из `logs/ui.log`.
- из верхней полосы окна удалена мелкая дублирующая подпись OmniBridge;
- раздел и плитка `VS Code Интеграция` переименованы в `Интеграция`, техническое назначение VS Code сохранено в описании.
- устранено закрытие приложения кнопкой сворачивания: окно работает в постоянном WPF application loop, скрывается в Tray и восстанавливается без завершения controller/Core.
- Tray получил собственное тёмно-синее меню: брендированная шапка, состояние Core, иконки навигации, hover/pressed-состояния, разделы навигации и управления, отдельные кнопки перезапуска и выхода.

## Проверки

- `go test ./...`, `go vet ./...`, `go test -race ./...`;
- XAML XML parse и PowerShell parser;
- lifecycle/UI/build-contract regressions;
- native Core smoke и shutdown;
- один Windows amd64 PE32+ GUI executable с ресурсами;
- SHA-256 manifests и проверка ZIP.

Нативное нажатие системного Tray и визуальный рендер WPF требуют Windows. Статические lifecycle-контракты проверены в cross-build-среде, а `scripts/validate-ui.ps1` выполняет WPF XamlReader-проверку на Windows.
