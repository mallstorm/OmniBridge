# Технический аудит OmniBridge 1.0.0-rc6

Дата аудита: 29 августа 2026 года.

## Итог

Проект представляет собой содержательный Windows-first AI gateway, а не макет: около 23,5 тыс. строк Go, 108 Go-файлов, 14 XAML-представлений, 12 PowerShell-скриптов, SQLite WAL, защищённое хранение секретов через DPAPI, маршрутизация, fallback/circuit breaker, протокольные адаптеры, статистика, Model Doctor, MCP control plane и локальный WPF/Tray UI.

После исправлений исходники проходят полные Go-тесты, race detector и vet; Windows x64 Core и Setup собираются кросс-компиляцией. Основные RC6-функции Yandex реализованы последовательно: нормализация native URI, метаданные моделей, разрешение URI/slug, фильтрация не-чатовых моделей для VS Code и корректные заголовки `Api-Key`/`OpenAI-Project`.

До аудита найдены четыре подтверждённых дефекта: Windows SQLite возвращал `REAL` как строку; RC6 показывал RC5 в статических XAML и Windows manifest; один Go-файл не проходил `gofmt`; локальные API-ключи сравнивались обычным сравнением строк. Все четыре исправлены и покрыты проверками. Корневой `SHA256SUMS.txt` также относился к RC5 и был регенерирован.

Главный оставшийся риск — механизм обновлений проверяет самосогласованный SHA-256 manifest, но не криптографическую подпись издателя. Злоумышленник, способный заменить ZIP, может заменить одновременно и файлы, и manifest. Для публичного канала обновлений до стабильного `1.0.0` нужна Ed25519/Authenticode-проверка доверенного ключа.

## Архитектура

| Слой | Реализация | Оценка |
|---|---|---|
| Gateway | `net/http`, localhost по умолчанию, TLS + CIDR для remote | Хорошая fail-closed база |
| Протоколы | Chat Completions, Responses, Messages, Embeddings, SSE, downstream WebSocket | Сильная текстовая/agent совместимость |
| Провайдеры | Data-driven catalog + native executors + OpenAI-compatible templates | Масштабируемо, но уровни поддержки надо явно показывать пользователю |
| Маршрутизация | priority/fallback, weighted, RR, least-used, P2C, quota/cost, auto, session affinity | Выше среднего для локального gateway |
| Надёжность | bounded concurrency, retry, persistent circuit breaker, panic recovery, graceful flush | Хорошо; нужны chaos/Windows acceptance tests |
| Хранилище | SQLite WAL + JSON compatibility mirrors | Практично для portable Windows, но двойная запись требует контроля рассинхронизации |
| Секреты | DPAPI CurrentUser на Windows | Подходит локальному продукту; non-Windows fallback не является production security |
| UI | PowerShell 5.1 + WPF/XAML + Tray | Удобно для portable-продукта, но сложнее тестировать и развивать, чем отдельный compiled UI |
| Release | self-described metadata, SHA-256, rollback, readiness | Хорошая основа, но отсутствует подпись издателя |

## Реальная поддержка провайдеров

В каталоге 92 определения, однако это не 92 одинаково полноценных native-драйвера:

| Уровень | Количество | Смысл |
|---|---:|---|
| Native | 5 | OpenAI, Anthropic, Gemini, GigaChat, Yandex |
| Preset | 18 | Проверенные OpenAI-compatible endpoints |
| Local | 4 | Ollama, LM Studio, vLLM, LocalAI |
| Local template | 14 | Пользователь задаёт локальный endpoint |
| Template | 47 | Требуется endpoint/deployment конкретного аккаунта |
| Reserved | 3 | Cohere, AI21, Replicate — native protocol ещё не реализован |
| Custom | 1 | Универсальный same-origin OpenAI-compatible probe |

Такое разделение технически корректно. В UI и документации следует всегда писать «92 определения каталога», а отдельно — «5 native + 18 preset», иначе пользователь может ожидать одинаковую глубину поддержки, включая streaming/tools/usage, от каждого элемента списка.

## Найденные проблемы

### Исправлено в ходе аудита

1. **Windows SQLite `REAL` менял тип данных.** Linux/cgo возвращал `float64`, Windows-обёртка — строку. Это могло ломать стоимость, score и другую числовую телеметрию. Windows-код теперь разбирает каноническое числовое представление SQLite в `float64`; добавлен Windows-only regression test. Заодно закрывается handle при ошибке `sqlite3_open_v2`.
2. **Version drift RC5/RC6.** `CurrentVersion`, `VERSION.txt` и `RELEASE.json` были RC6, но XAML и Windows assembly manifest оставались RC5. Исправлены XAML defaults и manifest `1.0.0.6`; новый тест связывает все источники версии.
3. **Невалидный исходный manifest.** `SHA256SUMS.txt` содержал хеши RC5 и не соответствовал изменённым RC6-файлам. Manifest регенерирован только после всех исправлений и проверок.
4. **Обычное сравнение API-ключей.** Для data/admin plane применялось строковое `==`. Теперь сравниваются SHA-256 digests через constant-time operation.
5. **Форматирование.** `internal/stats/stats.go` не проходил `gofmt`. Исправлено; CI теперь имеет отдельный formatting gate.
6. **Устаревший release toolchain.** Workflow был закреплён на Go 1.23.x. По политике Go поддерживаются только два последних поколения, а 1.23 давно не получает security fixes. CI переведён на Go 1.27.x при сохранении language compatibility в `go.mod`.

### Остаётся до стабильного релиза

1. **Нет подписи обновления — высокий приоритет.** SHA-256 защищает от случайной порчи, но не подтверждает издателя. Нужны `SHA256SUMS.sig`, встроенный public key и fail-closed verification до распаковки/копирования. Для EXE желательно добавить Authenticode.
2. **Обновление допускает downgrade.** Update проверяет целостность и readiness, но не требует, чтобы новая SemVer была выше текущей. Нужен monotonic version gate с отдельным явным флагом для rollback.
3. **Один общий data key и один admin key.** Нет virtual keys, отдельных потребителей, scopes, per-key limits и отзыва одного клиента без ротации всех интеграций.
4. **Нет token/request rate limiting по потребителю.** Глобальные concurrency slots защищают процесс, но не обеспечивают fairness, бюджеты и квоты между клиентами.
5. **Ограниченная мультимодальность endpoints.** Есть vision в canonical model, но нет унифицированных `/images`, `/audio`, `/rerank`, `/batches` и file API.
6. **Windows acceptance не выполняется локально.** Cross-build подтверждён, но WPF, PowerShell 5.1, DPAPI и `winsqlite3.dll` должны пройти GitHub Actions на реальной Windows VM.
7. **Покрытие неравномерно.** Хорошо покрыты health/security/stats/provider definitions, но `cmd/*` и secret store имеют 0%, server около 49%, storage около 46%, MCP около 31%.
8. **Нет SBOM и автоматического vulnerability gate.** Внешних Go runtime dependencies почти нет, но стандартная библиотека входит в бинарник; release pipeline должен выполнять `govulncheck`, публиковать CycloneDX/SPDX SBOM и фиксировать точную версию toolchain.

## Сравнение с похожими gateway

| Возможность | OmniBridge RC6 | LiteLLM | Portkey Gateway | Bifrost | Envoy AI Gateway |
|---|---|---|---|---|---|
| Основной формат | OpenAI + Anthropic/Responses translation | OpenAI unified API | OpenAI unified API | OpenAI-compatible | OpenAI-oriented Gateway API |
| Провайдеры | 5 native, 18 preset, большой template catalog | 100+ providers | 250+ LLM integrations | 23+ providers | Меньше native providers, но Kubernetes-native extensibility |
| Fallback/load balancing | Да, включая persistent breaker и auto router | Да | Да | Да | Traffic policy/fallback foundation |
| Virtual keys / tenancy | Нет | Да | Платформенные controls | Enterprise governance | Kubernetes policies |
| Guardrails | Context Guard, capability checks | Guardrails | Guardrails | Enterprise guardrails | Policy integrations |
| Кэш | Только учёт provider prompt cache | Provider/response caching | Cache/guardrail ecosystem | Semantic cache | Через расширения/policies |
| Observability | SQLite traces + Prometheus | Spend/logging/integrations | Local logs + platform observability | Real-time UI + plugins/OTel | Native metrics/logging/tracing |
| MCP | Registry/control/probe | Развивается | MCP Gateway | MCP gateway | MCP roadmap/route support |
| Развёртывание | Portable/installed Windows | Server/Docker/Kubernetes | Node/Cloudflare/Docker | Binary/Docker/Helm | Kubernetes/Envoy |

OmniBridge выгодно отличается локальным Windows UX, account connectors, Model Doctor и глубокой связкой Doctor → Router. Аналоги сильнее в multi-tenant access control, guardrails ecosystem, deployment automation, semantic cache, OpenTelemetry и широте non-chat endpoints.

## Рекомендуемая дорожная карта

### P0 — перед `1.0.0`

- подписанные обновления и Authenticode;
- запрет неявного downgrade;
- Windows CI acceptance для DPAPI, SQLite REAL, PowerShell 5.1 и WPF resources;
- `govulncheck`, SBOM, точный toolchain provenance;
- provider conformance suite: models/chat/responses/stream/tools/usage/error normalization для каждого native/preset provider.

### P1 — эксплуатационная поддержка

- virtual keys со scopes, expiry, revoke, per-key budgets и rate limits;
- OpenTelemetry traces/metrics/logs с контролем cardinality и отключением content logging;
- health-aware adaptive load balancing на фактическом EWMA latency/error rate;
- UI-матрица фактических capabilities и уровня поддержки каждого провайдера;
- signed remote release feed с channel (`stable`, `rc`) и release notes.

### P2 — расширение продукта

- `/images`, `/audio`, `/rerank`, `/batches` и files;
- опциональный semantic/exact cache с privacy policy и per-provider invalidation;
- provider SDK/plugin contract вместо роста central switch logic;
- headless Windows Service и отдельный portable Desktop client;
- опциональная Linux/Docker сборка для серверного сценария.
