Ты выступаешь как **ведущий UI/UX дизайнер + desktop product designer + implementation architect**.
 Твоя задача — выполнить **полный редизайн интерфейса OmniBridge** и довести его до уровня premium desktop-приложения по качеству, визуальной целостности и продуктовой зрелости.

## 1. Контекст приложения

Приложение называется **OmniBridge**.
 Это **Universal AI Gateway** — локальный мост/шлюз для подключения AI-провайдеров, моделей, аккаунтов и интеграции с VS Code.

Основные разделы приложения:

1.  Статус 
2.  API Ключи (Setup) 
3.  Аккаунты (Login) 
4.  Модели 
5.  Model Doctor 
6.  Интеграция 
7.  Логи 
8.  Настройки 
9.  О программе 

Текущее приложение визуально ещё сыровато, местами похоже на инженерный UI.
 Нужно привести **все экраны** к общему стилю уровня premium dashboard.

---

## 2. Главная цель редизайна

Нужно добиться следующих ощущений:

-  интерфейс выглядит как **завершённый релизный продукт**; 
-  всё визуально собрано в единую систему; 
-  у пользователя нет ощущения “PowerShell/WPF-формы”; 
-  все блоки выглядят кастомно и современно; 
-  приложение похоже на дорогой AI control center; 
-  каждый экран должен быть красивым и логически завершённым; 
-  не должно быть случайных белых полей, технических строк, невыравненных кнопок, перегруженных заголовков и системных элементов Windows по умолчанию. 

---

## 3. Ограничения окна и платформы

Это **оконное приложение**, не fullscreen.
 Размер окна должен быть фиксированным, близким к:

- **1137 × 706 px**
   или очень близко к этому. 

Требования:

-  окно не растягивается; 
-  без лишних вертикальных прокруток там, где экран можно уместить в фиксированный layout; 
-  интерфейс должен быть идеально собран в рамках фиксированного размера; 
-  всё должно помещаться и выглядеть как полноценный desktop dashboard. 

Если для технологии потребуется адаптация, допустим размер в очень близком диапазоне, но визуально нужно сохранить именно такой формат.

## 4. Визуальная концепция

Сделай визуальный стиль на основе следующих принципов:

### Цветовая схема

Основа:

-  фон приложения: очень тёмный сине-чёрный; 
-  внутренние панели: глубокий navy / blue-black; 
-  карточки: чуть светлее основного фона; 
-  границы: тонкие, холодные, полупрозрачные; 
-  свечение: мягкий blue/violet glow; 
-  акценты: 
  -  зелёный — success/status, 
  -  голубой/синий — основные действия, 
  -  фиолетовый — premium/action, 
  -  жёлтый/оранжевый — warning/partial, 
  -  красный — error. 

### Формы

-  большие скругления: 12–18 px; 
-  кнопки — аккуратные, единые, без “стандартного Windows-стиля”; 
-  карточки — мягкие, с глубиной и чётким ритмом. 

### Тени и glow

-  очень умеренно, дорого; 
-  без кислотных эффектов; 
-  акцентные свечения только там, где это усиливает premium look.

## 5. Типографика

Нужна чёткая иерархия:

### Уровни:

-  Заголовок экрана: крупный, bold/semi-bold. 
-  Подзаголовок экрана: muted, меньше, служебный. 
-  Названия карточек: medium/semi-bold. 
-  Показатели/KPI: заметные крупные числа. 
-  Вторичный текст: серо-голубой muted. 
-  Подписи полей: uppercase / kicker style, аккуратные, компактные. 

Важно:

-  название в левом верхнем блоке **OmniBridge** сделать компактнее, чтобы не конфликтовало с остальной компоновкой; 
-  подпись **Universal AI Gateway** должна быть меньше и мягче; 
-  версия — ещё меньше, с muted-оттенком.

## 7. Требования ко всем остальным экранам

Нужно привести **все страницы** к тому же визуальному уровню.

### 7.1 API Ключи (Setup)

Экран должен быть product-level, а не инженерной формой.

Нужно:

-  слева карточка “Подключённые API”; 
-  справа карточка “Добавить провайдера”; 
-  единая кастомная тёмная форма; 
-  никаких белых полей; 
-  никаких технических объектов в поле провайдера; 
-  в списке провайдеров и пресетах отображать **человекочитаемые названия**, а не id/object/JSON; 
-  “Найти локальные AI” должно быть встроено в правую секцию, а не висеть как случайная кнопка вне сетки; 
-  нижние кнопки должны быть выровнены, аккуратны и единообразны; 
-  поля: 
  -  Провайдер 
  -  Название профиля 
  -  Base URL 
  -  API Key / Authorization Key 
  -  Scope (если нужен) 
-  вспомогательный hint блок; 
-  Primary CTA: “Проверить и добавить API”; 
-  Secondary CTA: “Синхронизировать VS Code”. 

### 7.2 Аккаунты (Login)

Нужно две верхние карточки авторизации:

-  ChatGPT / Codex 
-  Google Gemini 

И ниже список “Подключённые аккаунты”.

Требования:

-  аккуратные badge Account; 
-  единый визуальный язык; 
-  нижние action-кнопки выровнять; 
-  показывать только полезные человеку данные; 
-  не показывать мусорные/технические состояния; 
-  если аккаунт не подключён — красивый empty/idle state. 

### 7.3 Модели

Экран должен включать:

-  заголовок, 
-  подзаголовок, 
-  справа простой текстовый счётчик “N моделей” (без лишней плашки, если это выглядит чище), 
-  строку фильтров: 
  -  поиск, 
  -  фильтр по провайдерам, 
  -  фильтр по источникам, 
  -  кнопка обновить. 

Слева:

-  список или каталог моделей. 

Справа:

-  карточка деталей модели: 
  -  название, 
  -  способности: 
    -  Chat 
    -  Streaming 
    -  Tools 
    -  Vision 
    -  Reasoning 
  -  контекст, 
  -  последняя проверка, 
  -  primary action: “Запустить глубокую проверку”. 

Пустое состояние должно быть красивым:

-  иконка, 
-  заголовок, 
-  подзаголовок. 

### 7.4 Model Doctor

Сделай экран серьёзным, premium, аналитическим.

Нужно:

-  поле провайдер, 
-  поле лимит моделей, 
-  основная кнопка “Запустить проверку”, 
-  блок “Последний отчёт”, 
-  в заголовке этого блока аккуратно выровненная кнопка “Обновить”; 
-  4 KPI-карточки: 
  -  Успешно 
  -  Частично 
  -  Ошибка 
  -  Проверено 
-  пустое состояние в центре, если проверок ещё не было. 

Важно:

-  никаких нелепых верхних лишних плашек; 
-  поле лимита моделей должно быть вертикально корректно выровнено; 
-  все кнопки ровные и одной логики. 

### 7.5 Интеграция

Название пункта в меню можно сократить до **Интеграция**.
 Экран должен быть про интеграцию с VS Code, но без перегрузки текстом.

Блоки:

-  соединение, 
-  конфигурация, 
-  экспорт моделей, 
-  статус интеграции, 
-  действия: 
  -  синхронизация, 
  -  открыть папку конфигурации, 
  -  проверить состояние. 

### 7.6 Логи

Экран логов должен выглядеть как продуктовый лог-viewer:

-  красивый заголовок; 
-  secondary text; 
-  кнопки “Обновить”, “Открыть папку”; 
-  фильтр уровней логов; 
-  счётчик строк; 
-  большая тёмная log area; 
-  без хаоса и случайных смещений. 

### 7.7 Настройки

Блоки-карточки:

-  сервер, 
-  обслуживание, 
-  каталоги, 
-  резервные копии, 
-  перезапуск сервера, 
-  экспорт/import config. 

### 7.8 О программе

Компактный красивый about-screen:

-  логотип; 
-  название; 
-  версия; 
-  описание; 
-  ключевые возможности; 
-  кнопка открыть папку / документы / сайт, если нужно.

## 9. UX и логика отображения

Очень важно:

### Не показывать технический мусор

Нельзя выводить пользователю:

-  object-структуры, 
-  служебные id, 
-  внутренние JSON-представления, 
-  нечитаемые backend-поля, 
-  длинные технические строки, если можно заменить человекопонятной меткой. 

### Человекопонятные названия

Провайдеры, аккаунты, модели, источники — всё должно отображаться красиво и понятно.

### Пустые состояния

Для пустых списков обязательно:

-  иконка; 
-  заголовок; 
-  поясняющий текст. 

### Состояния

Нужно предусмотреть:

-  loading, 
-  empty, 
-  success, 
-  partial, 
-  warning, 
-  error, 
-  disconnected.
